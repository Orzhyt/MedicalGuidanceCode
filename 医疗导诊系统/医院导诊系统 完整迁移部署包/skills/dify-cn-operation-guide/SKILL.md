# 中文 Dify 操作指导

交付目标：学员从空白应用出发，只凭手册和配套原文、代码与实验凭据，就能在 Dify 界面逐步搭建，并知道每步完成后界面应是什么样。成品是实验结果；开篇可以展示成品，但不把成品 DSL 当作起点发给学员。

## 启动时先做

1. 明确本次交付是一份新手册、整份重做，还是在用户已改稿上做局部修订。修订时定位用户实际保存的文件，忽略 Word 锁文件，核对用户指出的段落和截图后再选底稿。用户确认的章节、文字、图和版式优先于旧脚本及旧稿。只改授权范围；局部修订不强制重做已认可章节。
2. 新写或整体重做前，读 [02 主样例及对照样例](references/approved-examples.md)，实际打开主样例，查看正文、配置表、图片位置、代码框和导航层级。样例是对照物，不是素材库；不要将它的业务规则、节点数量、账号、主机或截图复制到新案例。
3. 读 [从零搭建与实拍流程](references/build-and-capture.md)；写正文时读 [逐步编写与配置表达](references/step-authoring.md)；交付 Word 前读 [Word 版式、导航及交付验收](references/word-and-acceptance.md)。这些文件是本技能的执行细节，不以这几条摘要代替。
4. 使用可用的 documents 技能完成 DOCX 编辑、渲染及检查；使用 Step by Step 实验手册模板的保留参考文件维持用户认可的封面、章节、页眉页脚和目录。Dify 现有业务逻辑和本机运行前提用 dify-business-workflows 的相关参考核验。界面实拍走可用的浏览器或 Computer Use 能力；具体界面词以目标版本和语言的实际 UI 为准。

## 一次写好的主线

- **先做实验清单，再写手册。** 从实际应用或 DSL 读取节点、边、变量类型、表达式、默认值和依赖，按初学者可执行的顺序安排。准备实验文件、数据、模型、服务、凭据来源和测试用例。保留经确认的现行业务行为。
- **总览在前，步骤在后。** 开篇放业务流程图、完整成品实拍、按步骤编号的节点总表。知识库用独立小节完成上传、索引、可用状态和召回；从“创建空白应用”起进入搭建章节。无知识库的流程跳过知识库章，不能硬套案例。
- **边搭建、边记录、边拍图。** 在独立空白应用里按步骤搭建，完成一个节点才拍当前配置，拍完才继续。不得用原成品画布截图代替过程图，也不得把半配置状态当成完成态。每个节点步骤至少有一张真实完成态；复杂面板只在必要时拆分截图。
- **每步写明添加入口、填写顺序和完成检查。** 先交代从哪个上游节点或哪条分支添加什么类型、命名为什么，再写可执行的配置。输入、输出、环境／会话变量、判断条件和 HTTP 配置用表格。待选择、填写、绑定的词和值按样例使用蓝色 #4F81BD；说明文字保持正常颜色。
- **代码按输入 → 完整代码 → 输出编排。** 每个代码节点把完整可运行源码放在本步可复制的浅底边框内，逐字符保留注释、空行和缩进；不得只贴开头、用省略号或用外部文件代替。提示词、模板、JSON 同样清晰标框；涉及变量令牌时说明如何用选择器重新绑定。若同一张实拍能读清输入、编辑区和输出，就放在该步末尾，少放重复过程图。
- **跑完整案例，再检查 Word。** 以可观察结果检验每条关键业务路径。没逐项在界面重录或没跑某个测试，就如实区分实拍、阶段写入、预期结果及实跑记录。核对 Step 在桌面 Word 导航栏的真实层级、正文目录、图号、配置和源码，渲染后再交付。最终只保留确认版和必要配套文件，清理旧稿须有用户授权。

## 完成标准

没有实拍的节点、没有完整源码的代码节点、没有字段来源的配置表、只有文字编号但不进导航栏的 Step、无法复现的关键路径，都不能称为最终验收完成。遇到环境限制，先解决前提；确实未能完成时，交付中明确剩余项，不能借用无关截图或用“已全部验证”掩盖。
