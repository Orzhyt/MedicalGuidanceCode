# 认可样例及实际阅读方法

## 主样例：02 医生档期预约

打开 [02 医生档期预约操作指导.docx](../assets/examples/02-booking-final.docx)。这是用户基本认可、随后修正了 Word 导航栏层级的最终样例。旧文件名中带“从零搭建实验操作指导”的同名近似稿曾存在样式 ID 错配，不要用它替代这里的参考版本。

按以下顺序审阅：

1. 第 1 章：业务状态图和 Dify 完整画布分别说明业务与实现。看其后节点总表如何把序号、节点名、类型和作用与正文 Step 对齐。
2. 准备与创建：应用从空白 Workflow 开始；名称、应用类型、默认画布和服务变量都有实际说明。观察 API_BASE_URL 与 SERVICE_API_KEY 是不同类型、不同配置图；截图用占位凭据。
3. Step 1：输入表包含变量名、字段类型、标签、必填与长度，截图展示已创建的两项字段。
4. Step 2 和 Step 7：先表格列输入，再给完整 Python3，再表格声明输出；完成态图放在步骤末尾，同图对照输入、编辑区和输出。代码框中的源文本是复制源，截图只确认代码已进入正确编辑器，不要求整份代码在一张图里都可见。
5. Step 3–6：用条件表、HTTP 表、模板框和聚合来源分别讲清主分支与错误分支，能看出 IF／ELSE 出口和合流去向。HTTP 的 URL、头、体、超时、重试及默认值都可据此复现。
6. Step 8 与测试章：结束节点给出输出名、类型及上游来源；输入示例后有实际结果截图。样例的独立草稿实际验证了参数错误用例；需要实验凭据的查询、占位、确认、取消列为验收任务。不能把这些预期结果当成该草稿实跑通过。
7. 在桌面 Word 中打开导航：展开“逐步搭建预约工作流”，应能定位 Step 1–8。目录仍保留与 01 相同的两级排版，导航层级不靠在标题里多打一遍 Step。

样例是交付质量参照。其阶段截图来自独立草稿，部分配置通过程序按阶段写入；不得据此声称原样例的全部字段都是手工录入并逐步复跑的。新项目应尽量按教材实际操作验收，并准确说明验证方式。

## 对照样例：01 咨询追问推荐

打开 [01 咨询追问推荐操作指导.docx](../assets/examples/01-consultation-final.docx)。重点对照有知识库、会话状态、多路分支、LLM 和长代码的写法：

- 知识库先建、先测试，再创建 Chatflow。配置使用原文、分段和召回实拍，输出 result 由平台生成。
- 会话变量与环境变量各用表格，实际值、来源和默认值分开。第一次配置的操作图关闭无关节点面板。
- 两个 HTTP 请求节点用同一种配置表；查看 GET 与 POST 请求体的差异。错误默认 JSON 保持代码框。
- 长步骤依旧保持输入、完整代码、输出的顺序。对照变量来源用具体节点名和输出名。
- 学习用户标出的蓝色 #4F81BD，以及已经修复的 Step 导航与连号。对照图号连续，不保留删图后的旧图注。
