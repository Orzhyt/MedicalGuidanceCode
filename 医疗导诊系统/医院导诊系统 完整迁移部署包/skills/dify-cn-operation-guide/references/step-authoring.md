# 逐步编写与配置表达

## 章节与每步结构

- 开篇介绍角色、场景、实验目标和边界。用业务流程图说明业务状态和决策，用完整画布说明平台实现。业务图如果要求可编辑，用 Word 形状和可编辑文本保持框、箭头和分支标签；不要改成表格，也不要把平台实拍改画成示意图。核对 Word 中框和线上的文字不被裁切。
- 在成品图附近放“工作流节点总览”：序号、节点名称、节点类型、作用。序号与正文搭建步骤对应。学员可以先看系统怎样工作，再找具体节点如何建。
- 正文按准备、知识库（如需要）、空白应用和变量、逐步搭建、运行验收组织。用真实的 UI 名称和操作动词，不用“导入成品后查看”。一个节点的必要配置应在该步连续出现，不把代码和输出说明零散放到与操作脱节的章节。
- 每步顺序：说明从哪个节点或哪条分支点击添加、选择什么节点类型、改成什么节点名；按界面顺序填写、绑定与连接；最后放完成态及可当场检查的项目。必须等全图才可运行的结果，统一放到测试章。
- 明确区别节点类型、用户命名、变量名、变量来源和业务解释。正文中文名词用中文双引号。代码、JSON、表达式、提示词中的引号及方括号不做排版替换。

## 按配置类型写表

| 场景 | 必须写出的字段 |
|---|---|
| Start / 用户输入 | 变量名、字段类型、标签、必填与否、长度、选项和默认值（适用时）。系统输入注明由平台自动提供、不必手工新增；无自定义输出就明说。 |
| 环境变量 | 变量名、类型和值。将 String 地址和 Secret 密钥分开；凭据写向讲师或管理员获取，截图和示例用占位值。 |
| 会话变量 | 变量名、类型、默认值。说明自动或显式写回的节点与下一轮用途。 |
| 节点输入 | 变量名、类型、取值来源。使用“上游节点名.输出名”；有多个输入，放同一张表。 |
| 节点输出 | 输出名、类型、来源或含义。Code 输出需手动声明且与返回字段一致；Template 的 output、LLM 的 text、知识检索的 result 等自动产生。 |
| IF／ELSE | 分支、取值来源、运算符、比较值、接入节点。字符串的“是”与“包含”不是一回事，数值等号依实际 UI。ELSE 不填比较值；两条路径汇入同一个节点时写清不要建两个副本。 |
| HTTP 请求 | 请求方法、URL、每个 Header 单列、请求体类型与来源或“无”。同时交代鉴权模式、超时、重试和异常处理；字段多时另做参数表。异常默认 JSON 可复制，放浅色边框，不换成难复制的字段摘要。 |
| 聚合器 | 类型、每条分支的输出来源、是否启用分组、最终输出名。 |
| 变量赋值 | 目标变量、覆盖或其他操作、取值来源。 |
| Answer／End | 直接回复只绑定应向用户显示的变量。End 输出表列字段、类型、取值来源；不要遗漏真实业务状态字段。 |

表格视觉以主样例为准：清楚的表头、浅色数据行，字段充分展开而不挤成竖排。保持同类配置在全文同一种写法，包括后面的第二个 HTTP 节点。行较少时尽量整表同页，跨页重复表头。

## 代码、模板、提示词与变量引用

- 代码节点固定顺序：输入表 → 选 Python3／JavaScript → 复制完整代码 → 输出表 → 完成图。原代码按实际流程读取，并与交付 Word 文字逐字符比对。不要省略 import、注释、空行、尾部代码或缩进，不插入行号、提示语、花括号替换、截断或省略号。截图和配套代码文件是补充；完整代码必须在正文。
- Word 中用浅底边框和等宽字体表示复制区，允许视觉折行和跨页，避免因长行而删字符。不要为了每步一页压缩到无法阅读。不要用图片作为唯一可复制材料。
- Template 写明输入变量与完整模板，保持 Jinja 标点原样。LLM 分角色放完整 SYSTEM／USER 等提示词，列模型、温度、最大输出、结构化设置、记忆、重试和异常配置（以实际应用为准）。
- 复制 LLM 提示或 HTTP 变量时，旧应用中的节点 ID 不能在新应用通用。对教材中的占位标记明确说明用变量选择器插入具体来源，避免把占位文字或旧引用当成普通字符串。完整代码的字符不要因此被改写。
- 蓝色 #4F81BD 只标学员要选、填或绑定的内容，例如节点类型、节点改名、变量名／来源、参数值、按钮。正常解释、图注和段落标题保留模板色，复制区保持原文本；不依赖颜色单独传达必填和类型。

## 审读方式

逐步站在学员视角查四件事：我在哪个页面、点哪个位置、填什么或从哪里选、填完应看到什么。凡缺一项就补。检查测试输入能直接复制、需替换的编号与凭据都有来源。开篇图、节点表、正文步骤、配图、条件出口与实际应用名字要互相对上。先修实质遗漏，再修排版，不要靠最后堆图和格式掩盖步骤不完整。
